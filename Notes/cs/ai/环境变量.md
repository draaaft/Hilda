## 环境变量介绍

环境变量（Environment Variable）是操作系统中用来存储系统配置信息的动态命名值，它们影响着程序的运行方式和系统行为。
在调用大模型时，通常设置环境变量来传递API密钥等敏感信息，从而避免将key直接写在代码中。（因为代码通常会传到github之类的地方，导致key泄露）

## 基本概念

**环境变量**是键值对形式的数据，例如：
- `PATH=/usr/local/bin:/usr/bin:/bin`
- `HOME=/home/username`
- `LANG=zh_CN.UTF-8`

## 主要作用

### 1. 系统配置
- **PATH**：指定可执行文件的搜索路径
- **HOME**：用户主目录位置
- **TEMP/TMP**：临时文件存放位置

### 2. 程序运行环境
- **LANG/LC_ALL**：语言和区域设置
- **JAVA_HOME**：Java安装路径
- **PYTHONPATH**：Python模块搜索路径

### 3. 应用程序配置
- **DATABASE_URL**：数据库连接字符串
- **API_KEY**：API密钥
- **NODE_ENV**：Node.js运行环境（development/production）

## 环境变量的作用域

### 1. 全局环境变量
- 对所有用户和进程生效
- Linux：`/etc/environment`、`/etc/profile`
- Windows：系统属性 → 高级 → 环境变量

### 2. 用户级环境变量
- 仅对特定用户生效
- Linux：`~/.bashrc`、`~/.profile`
- Windows：用户环境变量设置

### 3. 进程级环境变量
- 仅对当前进程及其子进程生效
- 通过命令行临时设置
- 关闭进程就会丢失

## 常用操作

### Linux/macOS
```bash
# 查看所有环境变量
env
printenv

# 查看特定变量
echo $PATH

# 临时设置（当前会话）
export MY_VAR="value"

# 永久设置（写入配置文件）
echo 'export MY_VAR="value"' >> ~/.bashrc
source ~/.bashrc
```

### Windows
```cmd
# 查看所有环境变量
set

# 查看特定变量
echo %PATH%

# 临时设置
set MY_VAR=value

# 永久设置（命令行）
setx MY_VAR "value"
```

## 最佳实践

### 1. 安全性
- **不要**在环境变量中存储明文密码
- 敏感信息使用专门的密钥管理服务
- 注意环境变量可能被日志记录

### 2. 命名规范
- 使用大写字母和下划线：`DATABASE_URL`
- 添加前缀避免冲突：`APP_API_KEY`
- 保持命名语义清晰

### 3. 配置管理
```bash
# 使用 .env 文件（开发环境）
DATABASE_URL=postgresql://localhost/mydb
API_KEY=your_api_key_here

# 通过代码加载
# Node.js: require('dotenv').config()
# Python: from dotenv import load_dotenv
```

### 4. 常见问题
- **变量未生效**：检查是否需要 `source` 配置文件或重启终端
- **子进程无法访问**：确保使用 `export`（Linux）或 `setx`（Windows）
- **路径包含空格**：使用引号包裹值

### 环境变量的存储位置

环境变量并非存储在单一位置，其存储方式取决于操作系统和变量类型（系统级或用户级）。在程序运行时，它们通常保存在进程的内存环境中；而需要持久化保存的配置，则各有不同的文件和数据库。

#### 持久变量
Windows 系统
在 Windows 中，持久化的环境变量主要存储在注册表中：

用户变量：存储在 HKEY_CURRENT_USER\Environment 项下，仅对当前用户生效。

系统变量：存储在 HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Session Manager\Environment 项下，对所有用户生效。

Linux 系统
Linux 的存储方式较为分散，取决于变量的作用范围和管理机制：

系统级配置：常见于 /etc/environment（由 PAM 模块读取，格式简单），或 /etc/profile 及 /etc/profile.d/*.sh（由 Shell 读取，可执行脚本）。此外，environment.d 目录（如 /etc/environment.d/*.conf）也是 systemd 体系下的配置位置。

用户级配置：通常位于用户家目录的 Shell 配置文件中，例如 ~/.bashrc、~/.bash_profile 或 ~/.profile。

### 进程级环境变量
进程运行时：对于正在运行的进程，其环境变量实际上存储在内存中，但可以通过 /proc/[PID]/environ 文件查看（该文件以只读方式呈现进程的环境块）。

macOS 系统
macOS 同样基于 Unix 传统，配置分散在 Shell 配置文件中：

全局配置：如 /etc/profile、/etc/paths（专门用于定义 PATH）。

用户配置：如 ~/.bash_profile、~/.zshrc（取决于所用的 Shell）。

补充说明：无论存储在哪个文件或注册表中，当程序启动时，操作系统会将这些配置加载到该进程的内存空间里。子进程通常会继承父进程的环境变量，这也是为什么你在终端里 export 的变量只在当前会话及其启动的子进程中有效，关闭终端或新开窗口后可能就会失效（除非写入了上述的持久化配置文件）。
而持久的环境变量也是直接写入硬盘中的，总是存在被读取的可能，所以也并非绝对安全。进程级的则只写在内存中，不会被持久化存储，但是它需要每次启动进程时都重新写入，没有那么方便。
